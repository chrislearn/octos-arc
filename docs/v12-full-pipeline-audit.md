## 仍需线上验证的边界

- **缓存收益**：提示词保留稳定的通用指令前缀，同一类别共享上下文，工作者先预热一个请求再并行派发。线上 v11.12 取消前没有用量汇总，无法计算真实缓存命中率、账单 token 或 v12 提速倍数。下一次 v12 运行应比较阶段记录中的 `cache_hit_tokens / prompt_tokens`，并与平台计量核对。
- **审核总回合**：两次硬上限针对每节点场景提案。独立用例审核可能因多用例、无效 JSON、遗漏 ID 和修正后的新版本产生额外请求；这些请求有全局次数、时间和 token 预算，并且失败时保持待审。若要把不同用例的独立审核也硬压成每节点两次，必须先保证批次能容纳全部用例且缺失回复仍可安全重审，否则会降低覆盖。
- **并行吞吐**：v12 的独立工作者最多 2 个并发，文本只在主线程校验和写入；义务独立复核、规则修正、审核修正和代码写入仍按依赖顺序执行。并行减少等待，但总 token 未必下降，且模型端限流、长尾请求与大提示词可能抵消收益。
- **成品正确性**：本地单元测试能验证调度、隔离与错误处理，不能代替线上完整需求的功能测试。下一条完整 v12 运行必须观察最终启动演练、节点验收、全套结果、未审核缺口和浏览器运行错误；取消运行不能提供最终结论。
