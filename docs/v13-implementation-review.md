## low 推理档位

原代码对 `qwen3.7-plus`、`glm-5.3-flash` 的设计、审核、实现与修复默认选 medium。v12 本地 medium 运行中，推理内容占已计量 completion 的 41,887/72,746，约 57.6%；首次实现波次为 21,769/25,801，约 84.4%。将这两类模型的默认档位改为 low 后，所有默认阶段均为 low，显式用户配置仍可覆盖；`none`、路由参数和供应商的独立预算参数保持原有语义。[阿里云官方接口文档](https://www.alibabacloud.com/help/en/model-studio/qwen-api-via-openai-chat-completions)将 low 定义为较低强度推理。减少推理 token **可能**缩短长请求，但本机没有该端点的在线凭据，无法提供同题 low/medium 实测时长或质量差异。以本次约 58 completion token/秒计算，消除全部推理 token 的算术上界约为 12 分钟；low 不会消除全部推理，这个数字不是预期提速。

## 仍需验证

- 跑同一需求树、模型、预算的 low/medium 对照，比较首次可测试节点时间、有效场景覆盖、行为通过率、返工轮次、推理 token 与缓存命中。若质量显著下降，应恢复复杂阶段的 medium 显式设置。
- 运行完整 v13 线上任务，确认类别增量设计能在真实回复中保留跨节点合同、减少输出和重试；本次单元测试只证明合并规则与状态边界。
- 对同一任务按阶段统计输入缓存命中及提示词前缀复用。v13 没有改缓存键或把动态需求前移，避免未经验证的跨版本合同复用；输出推理 token 仍是已观测耗时的大头。
- Sheet 数字格式、批量原子性与 GitHub 合并冲突、双父提交属于两份旧生成产物的业务缺陷；修改本仓库运行器不能追溯修复已下载项目。后续应在这些用例经独立审核后以行为测试验证新产物。
