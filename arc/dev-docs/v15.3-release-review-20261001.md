# v15.3 改进、复审与交付验证

本次依据 `4f1ce8bdba65` 和 `647425dc8258` 的下载快照及上一轮复现证据修改适配器。详细原因见 [两次失败分析](4f1c-6474-repair-analysis-20261001.md)。发行包是适配器更新，内核仍为 `2.0.3-rc.11 (91bb5a44)`。

## 已落实的流程改进

1. 冻结且经过源代码复审的内部测试默认使用一个 worker，与当前默认最终验收一致。此类测试共享一个可变应用数据仓库；并发创建工作簿会破坏另一个 CSV 拒绝测试的整个列表前后相等断言。显式 `OCTOS_ARC_TEST_WORKERS` 和 `run_specs(workers=...)` 仍可覆盖默认值。未改变外部官方测试的默认并发。串行通过仅证明串行条件下的行为，不作为并发正确性证据。
2. 受影响回归复测记录完整测试文件范围和实际 worker 数。失败节点需要回滚归因时，先重新测量当前准备保留的源码，再恢复节点前源码，使用相同完整范围、worker 数、grader_like 启动方式和每次新建的私有数据目录复测。保留可能参与干扰的其他测试，避免同时改变源码和测试选择。缺少对照或测量不完整时不凭旧结果保留新节点。
3. 若完整对照显示所有失败的旧节点在恢复前源码后仍失败，新节点可恢复，但必须在实际恢复的源码上重新测量目标用例并通过。旧节点仍为未验证；不再将前后都失败直接描述为“已证明不是回归”。目标复测失败或未完成则恢复节点前源码。每次节点验收清除该节点上一次的对照记录，防止跨轮使用。
4. 结构化生成返回完整但未修改源码的 `unchanged` 结果时，工具兜底默认仅有 180 秒、8 次请求，且不再追加第二次空操作续跑。用 `OCTOS_ARC_NOOP_TOOL_SECONDS` / `OCTOS_ARC_NOOP_TOOL_REQUESTS` 调整这两个上限；仍受本轮剩余时间和总请求额度约束。缺少上下文、被拒绝的补丁、格式纠正或已有部分写入保留原来的恢复额度。
5. 达到结构化修复轮数后，目标节点已绿但受影响旧行为仍红，同样切换工具模式。避免只检查目标节点的通过数。
6. Python、内核所用完整 UI 合同、精简 codegen 及工具 repair 提示同时补充草稿原始对象与可变选区/焦点分离的规则。明确要求检查内层 commit 函数的条件，不能只去掉外层 blur 条件；提交和取消应使用草稿开始编辑时捕获的对象身份。保存旧对象的响应不能覆盖新选中对象的控件；加载、导航、指针选择和切换工作表时，当前选区、范围与最新选区 ref 必须保持一致。

## 复审关注点

- 完整范围可能包含在节点前源码上尚未实现的新节点；旧节点结论仅从对应旧节点的结果切片计算，其他用例保留作为环境中的参与者。
- 再次恢复新节点后不沿用之前 `node_passed` 的缓存结论，重新测量目标节点。条件性失败的旧节点不标绿。
- 内部测试的源码、断言、需求、原始下载快照不因适配器修复而改写。新增和更新的是适配器的开发单元测试。
- 回滚对照有额外验收成本；预算不足时保守恢复，不使用未测量状态做成功声明。
- 实际请求复审发现，单独修改完整 UI 合同不会传入精简 codegen 路径。已补齐 `CODEGEN_RULES` 和 `app_repair_prompt`，并新增测试检查经过结构化工具提示转换后的实际传递文本。实际请求中也核对了捕获编辑对象与检查内层 commit 条件两项规则存在。
- 快照中的公式栏错误属于应用生成代码，发行包不硬编码该工作表应用的补丁；必须由真实模型使用更新流程生成，并通过原始用例确认。

## 真实 Qwen 验证与发现的遗漏

使用 `.test_data` 配置实际调用 `qwen3.7-plus`，每次在隔离复制目录内运行。模型改动仅涉及 `frontend/src/pages/Editor.jsx`，原始冻结 TypeScript 测试、helpers 和需求保持逐字节一致；没有手工注入应用补丁。16 项原始用例对应快照当时已经实现的 13 个节点。

| 实验 | 结果 | 结论与后续处理 |
| --- | --- | --- |
| 初次范围检查 | 13/18，模型修复前终止 | 误纳入当时未实现的工作表切换/删除；保留日志，纠正测量范围，不计为有效修复实验。 |

## 上下文预算与信息传递

这些实验使用 `codegen_context_chars=196608`，这是字符上限，不是 token 上限；没有上下文超限拒绝。失败原因包括新规则漏入精简请求、模型保留内层错误条件，以及保存响应和选区同步遗漏，不能靠单纯增大预算解决。

r5 的人工源码线索最初放在长失败文本尾部，实际请求审计确认被截掉。r6 将这条线索放入关键待修正项，确认实际请求包含它和最终规则，模型一次请求完成该遗漏修复。本地验证入口已更新这项信息传递方法；没有把手工源码线索自动生成机制作为已实现的生产能力。

## 范围限制与后续工作

本次验证的是下载快照的本地修复与相邻行为，未重跑云端整任务。默认结构化路径的 r3 冷启动验证已通过原始用例；最终规则又经过 r5/r6 接续修复验证，没有宣称最终版本重新冷启动全量生成也已验证。FILE 冷启动 r4 的失败完整保留。

本次没有声称所有历史失败已经消失。GitHub 密码用例的两个合法错误提示同时出现导致严格联合 locator 冲突，仍保留为未验证，未删除提示或修改冻结测试。自动补齐全部祖先语义测试、通用种子迁移审计，以及从源码自动提取关键诊断线索仍是后续改进；新 UI 合同是模型约束，不能保证每次生成正确。
