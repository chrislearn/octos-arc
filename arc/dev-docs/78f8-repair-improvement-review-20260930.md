## 1. 为什么 v15.2 又改坏注册

云端使用的确实是已交付 v15.2，adapter 指纹为 `40031a4de0e5ecdfef393bd104c677c509c0df32a4881330ae3ad47e7a725045`。注册最初 3/3，登录后前两节点 8/8；修找回密码后变成 7/8。实际修改把原需求指定的 `Password requirements are not satisfied` 换成了另一句英文。缺失的是修改前的具体旧合同，泛泛要求“不要破坏已通过功能”不足以约束共享认证文件。

找回密码同时有两个独立缺陷：菜单未响应 Escape，导致 helper 第二次点击 Account menu 时反而关闭菜单，随后找不到 Sign out；修好后才暴露首页缺少 Forgot password 入口。把 React Router Link 换成原生 a 不能修复菜单状态。先前隔离控制实验分别修复文案、Escape 和首页入口，前三节点从 8/10 达到 10/10；这是明确的人工控制实验，不是模型修复成功率。

保存的云端日志截止北京时间 2026-09-30 22:35:31。长工具回合和心跳能够证明耗时，不能单凭它们断言无限循环。本轮没有继续轮询云端，也没有修改、暂停或取消云端任务。[原始分析与控制证据](/home/chris/Works/octos-arc/arc/diagnostics/78f8a2a9fb53-20260930/analysis.md) 保留了代码差异和各次失败位置。

## 2. 已实施改进

## 3. 更新后的具体流程

1. 从当前节点、spec、实际失败和源码索引确定此次范围；字面 React 路由可确认时，完整引用其真实页面组件，同时补上祖先共享约束及相关历史节点的原始合同。
2. 对完整提示计费前检查字符预算。旧合同不截断；文本模式无法交付完整约束时转工具模式读取原文。
3. 模型实际修改应用文件。响应不完整、补丁锚点失败和未获得必要源码时继续使用现有写入保护。
4. 测当前节点，再测受共享改动影响的历史节点。目标绿而旧节点红，继续双方联合修复；历史失败不会因一次省略重复测量而消失。
5. 若候选变得更坏并满足回滚条件，恢复最佳源码。单节点先重新测量恢复后的代码；完整套件同步回对应最佳快照的已测证据。不能继续诊断被拒绝补丁的 DOM 或错误位置。
6. 下一模型回合重新计算源码范围和旧合同；重复失败可切工具模式。轮数、时间、请求与 token 上限仍有效。
7. 当前目标和所有本轮历史复测义务都实测通过后才接受。加载失败、预算不足、冻结 oracle 冲突或不完整测量都不能当作成功。

## 5. 上下文预算与复审结论

在同一基线测量构造的实际提示词，把全局字符上限 196,608 提升到 393,216，A、B、C、D 的提示内容各自完全相同：116,035 / 116,126 / 116,094 / 120,572 字符，均能装下。相关历史合同约 5 KB；D 的父级加历史合同约 9 KB。因此本例没有扩大总上下文的必要证据；此前问题来自具体信息交付、错误诊断和回滚后证据过期，更多额度不会自动修好这些问题。没有用字符数推断 tokenizer 的实际上下文容量或费用。

复审已纠正：未来节点不能混入保护集合；单节点 description 提到旧 REQ ID 时不能误认成当前工作；文件范围改变必须重建 owner；巨大 spec 快速返回仍要阻止不完整合同的文本回退；重复动作的假设不能变成 verdict；包的显式文件清单不能漏掉新增 import；中途回滚必须先产生当前源码的新证据；实际页面源码不能依赖文件名猜测，构建配置不应混入浏览器路由树。已有测试桩补上新接口的空默认返回或真实 SourceIndex，没有删除原断言。

后续应优先补“错误操作 → 状态 → 路由 → 页面结果”的可测量关系，并在相同任务、模型和预算下做多样本完整运行。共享入口改动仍可能引入重复可访问名称；本轮依靠实际验收检测，没有硬编码隐藏一个合法入口以规避测试。依赖和源码 owner 选择是保守启发式，不能保证预测模型临时决定编辑的所有文件；最终回归仍不可省略。

后续改进按以下顺序验证：

- 优先做相同模型、预算和初始状态的多样本回放，分别覆盖正常旧节点继续开发、旧节点已回归的修复、完整套件回滚；记录实测通过、回滚次数、请求和 token，而不是只比较最后通过数。
- 对动态客户端路由和多层组件包装补充工具读取证据；静态映射无法确认时显式保持未知，不放宽到按名称推测页面归属。
- 继续核对共享入口的操作、状态、URL 和页面结果，在保持合法入口及原产品导航的前提下检查重名控件；记录框架选择与模型实际编辑范围的差异，校准 owner 选择。
- 只有观测到必需合同或源码被预算排除时才定向提高额度；同时保留总请求、时间和 token 上限，区分正常长回合、无编辑重试、源码变化后的重复失败和真正停滞。

前两次运行中发现的密码 OR 定位器冲突仍需独立版本化审核；这轮没有偷偷改其冻结测试，也不宣称整题 47 个节点或 ARC 最终评分通过。
