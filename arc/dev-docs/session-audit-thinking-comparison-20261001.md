## 修改后的流程

1. 固定原始需求及冻结测试，取得当前节点、祖先合同、相关旧功能合同和 public fixture 依赖；缺资料时先补读。
2. 生成按实验思考设置执行；接口/导出、原子编辑、静态冲突及可取得的真实路由注册检查通过后，写入候选。
3. 节点验收与受影响旧功能回归独立记录。超时保留已完成证据，全范围 unknown；确认启动故障与业务失败分别处理。
4. 正式修复始终开启思考，使用同一轮请求额度及节点剩余 deadline；更坏候选保留最佳状态，恢复后先复测再组下一提示。
5. 时间或成本不足就停止新修改；能测多少如实记录多少。最终保留 artifact、提交 completed/exit 0，平台评测产品结果。
6. 用户明确取消的 SIGINT 保持停止语义；可处理的基础设施 SIGTERM 尝试交付。外部 SIGKILL、宿主 OOM、掉电、不可写文件系统或解释器/依赖在受保护入口启动前已损坏，无法由该 Python 收尾逻辑保证产物成功落盘，不能承诺物理意义的“任何问题绝对不退出”。
