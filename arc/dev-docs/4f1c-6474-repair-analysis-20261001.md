**需要更新的流程，按优先级排序**

1. **先确认测量条件，再向模型收费修复。** 并行联合套件出现历史失败时，在相同源码上先串行复测相同选集，并记录初始数据、选集、worker 和浏览器配置。串行通过只能证明条件敏感，不能直接计为并行全通过。若还需判断变更因果，应对 pre/post 两份源码使用相同选集、相同调度配置和新鲜等价数据。无法保持条件时标为“不确定/状态干扰”，不要直接输出“shared-file edit regressed proven behavior”。
2. **给无修改诊断独立出口。** [node_repair_turn](/home/chris/Works/octos-arc/arc/main.py:6605) 目前在模型返回无修改后直接把剩余约 760/1043 秒交给工具 fallback。应先对“测试隔离/定位歧义”这类可验证诊断执行一次有界复核；确认后保持应用，登记测试问题。未确认才携带复核证据继续应用修复，不能让同一无修改结论重新消耗一个完整长回合。
3. **保护共享交互状态和渲染后的可访问语义。** 修改 Layout/Home、菜单/对话框、Editor/Grid 等组合时，在小范围共享契约检查中验证入口数量、实际 role/name、打开→Escape→重开、编辑→选区 mousedown→blur→持久化。已有父需求描述和源文件引用只是输入约束，无法阻止模型后续重新引入错误。草稿必须绑定不可变编辑对象，选择变化不能改变提交目标。修复进展及模式切换应覆盖目标与历史的联合失败；当前节点一直 1/1 不能让历史失败持续留在相同修复方式。完成声明必须与相关失败用例的实测绑定，不能以“改了事件外层”替代调用链验证。
4. **把起始数据检查前置。** 从提供的 fixture/需求抽取账户、组织、仓库及权限前置关系，验证种子初始化在首次启动和已有存储时都一致；不要等每个 UI helper 超时后分别补一组迁移。不得为了过用例给所有用户扩大真实权限。
5. **独立处理内部 oracle 缺陷。** 密码正则需要多个合法错误可共存的行为检查；CSV 全列表不变检查应在隔离运行中执行。保留原始失败及来源，不通过删应用错误、改正式测试或无证据排除失败来抬高成绩。内部套件如另发版本，需要重新复审、固定指纹并记录前后 oracle 差异。
6. **改善长回合日志。** 心跳外应记录脱敏的当前请求序号、累计工具读写、最后实际源码变化及最近验证结果。43 次工具调用不等于 43 次模型 HTTP 请求，不能据它判断 36 请求预算失效；现有 stdout 缺少细粒度数据，也无法区分每次等待是模型延迟、工具执行还是重复阅读。
