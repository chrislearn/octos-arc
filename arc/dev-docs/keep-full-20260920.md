## Observations to validate against the final outcome

1. First full measurement: **8/32 in 252 seconds**, but only six leaves had
   successfully completed generation. This is a partial-app score, not a complete
   first implementation. A single-leaf generation failure ended all later waves.
2. Wave 2 exhausted 32,768 output tokens: 240 EDIT blocks, 195 no-ops. Wave 4
   exhausted the same limit: 222 EDIT blocks, 217 exact repeats. The latter
   discarded every edit because the repeated tail contained invalid anchors.
3. An offline periodic-tail/no-op filter reduces wave 4 from 133,316 characters
   to 2,877 characters / four edits. All four anchors validate against its exact
   pre-request Git snapshot `bfc9a35`. This establishes protocol recoverability,
   not business correctness, and does not recover already spent tokens.
4. REQ-2.4 had 92 seconds remaining, REQ-2.5.1 had 146 seconds, and REQ-2.5.3
   had 260 seconds: all skipped repair because the default admission floor is
   300 seconds. A one-request code repair and a tool investigation need different
   admission policies. Explicit user limits must still be honored.
   This admission bottleneck is budget-dependent: the experiment's 2-hour total
   is substantially below the platform adapter's default 13h20m for 32 leaves.
   It does not prove that the unconstrained default always skips these repairs.
5. REQ-2.5.2 repair spent 137s on a truncated/invalid patch, 146s on a truncated
   retry, then another 59s on tools before testing. A safely applied partial patch
   should be measured before assuming another model call is necessary.
6. The generated card exposes an Edit button but clicking its title does nothing;
   archive is only inside a menu rather than directly reachable as required.
   These are operation-entry mismatches, not JSON response-envelope errors.
   Generic contracts must preserve the required gesture, target and action placement.
7. REQ-2.6.1 fails before changing color: `page.screenshot: Expected
   options.clip.height to be greater than 0`. The public helper computes a clip
   against viewport dimensions without first scrolling the target into view.
   This is a viewport/layout/helper interaction, not evidence that the color
   mutation failed. Do not alter official tests or reorder task-specific records
   solely to manufacture a pass.
8. Page diagnostics already contain accessibility trees, but `page_snapshot`
   clips the first 4,000 characters. A captured color-editor failure puts a long
   aria-hidden background list before the active dialog. Prefer the visible
   interaction subtree within the existing budget instead of adding a second
   verbose DOM dump. No test assertions or browser actions need changing.
9. The normal per-node `codegen_implement_prompt` uses only `description`, unlike
   wave prompts and tool-mode prompts which include `describe_node` scenarios.
   Preserve scenario actions/dependencies in every path, especially when a brief
   phrase such as "default label" could be mistaken for unconditional selection.
10. An observed label repair forced a fixed catalogue ID into every new record.
    That did not fix the failing interaction. Optional selections must reflect
    the user's draft; catalogue defaults are not automatically selected values.
11. The five route views duplicated `app-header` markup. REQ-6.1 then emitted
    two 32K replies while changing sidebar/layout styling; a CSS anchor failed,
    but the retry requoted eight files, including all five pages. Shared chrome
    should have one React layout owner (page content/headings remain slots),
    and application-error retries should specifically requote failed targets.

## General fixes under isolated regression

- Periodic EDIT-tail and no-op detection, atomic validation of retained edits,
  and explicit incomplete status. Meaningful ordered revisions are not globally
  deduplicated; a retained cycle preserves its final phase. No test verdict is
  inferred from response format.
- After detected degeneration, cap subsequent tool-less code requests at 8,192
  output tokens and constrain wave planning accordingly. Initial generation and
  design keep their original limits. This is containment, not proof of a quality
  improvement; `OCTOS_ARC_DEGENERATE_MAX_TOKENS=0` disables it.
- Optional recovery reasoning (`OCTOS_ARC_RECOVERY_REASONING=low`), disabled by
  default. No silent change to the user's thinking-off baseline.
- Continue later waves after one failed leaf; retain and measure partial waves
  before regenerating their work. Complete/partial/deferred counts are distinct.
- Measure safely applied partial repairs before spending another model call.
- Give codegen repairs a 60s default admission floor plus recent measured time;
  tools retain 300s, and explicit user floors override the default.
- Preserve per-node scenarios/dependencies; carry exact anchor errors into
  retries and only mark the failed files as needing requoting. Explicitly
  refused targets outrank the broad historical diff on suite retries; otherwise
  the same named file can be crowded out again and force a tool fallback.
- Build suite repair specs with the existing shared-helper batch formatter.
  The 11 failing Keep specs occupy 74,602 characters when each includes its own
  helper copy, versus 15,461 when reachable helpers are shared once. This frees
  room for more complete specs/source files; it is not a claim that the entire
  model request shrinks by 79%. Selected original requirement scenarios are
  preserved in suite repairs too, and omitted specs remain explicitly listed.
- Prioritize visible dialog/menu/listbox snapshots within the existing 4K
  diagnostic budget, without altering browser actions or official tests.
- Strengthen task-neutral interaction/selection/shared-layout contracts,
  including explicit mapping from presentation labels to CSS/API identifiers.
- Record actual output ceiling, request-time reasoning mode and provider finish
  reasons. Offline analysis reports raw-response pathologies separately from
  billed usage; replay tools never modify the source run.

No runtime source changes were loaded into the baseline process. Its results
must not be represented as a full rerun of these fixes.

The recovery output ceiling is experimental containment. It may produce smaller
waves and therefore more generation calls; reducing tokens per failed reply is
not sufficient evidence of fewer total calls or a higher pass rate. Fresh
end-to-end comparisons are needed before calling this policy optimal.

## First final-suite measurement (not yet the final delivered result)

After all 32 nodes completed their cycles, the first final suite scored **21/32
in 111s**, checkpoint `fc04f11`. The console's node-state tally was only 17 passed;
this demonstrates why individual, historically measured states are not a final
grade. Full report/context snapshots were preserved in
`...-diagnostics/full-suite-0-21/` before the runner overwrote its working report.

- REQ-2.4: clicking the record title does not open an editor; input lookup times
  out. The separate Edit button is not an equivalent required entry gesture.
- REQ-2.5.1–2.5.4: archive/undo/view/unarchive paths fail around the required
  control and resulting record visibility. Do not treat all as independent
  backend bugs; entry gestures and lifecycle queries must be traced together.
- REQ-2.6.1: unlike the earlier per-node viewport failure, this suite reaches
  the visual assertion and sees no change. Source uses `color-${note.color}`
  with values such as `light green`, while CSS defines `.color-light-green`.
  These are different class tokens; use a canonical option key/mapping rather
  than concatenating display labels into machine identifiers.
- REQ-2.6.2 and REQ-2.7.4: creation-option interactions time out.
- REQ-2.7.1/2.7.2: label assignment/removal fail around record selection or
  visibility. The shared card's menu `onOpenChange` also closes its label dialog
  whenever the menu closes; this contradicts independent menu/dialog ownership.
- REQ-2.7.5: label management never presents the expected usable input.

The matched low-mode replay fixes the first of these in isolation; it does not
prove the other failures are fixed. General contracts and runtime containment
must still be evaluated in a future fresh generation run.
