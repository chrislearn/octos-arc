复核对象为当前工作区中两轮运行调查相关改动，包括节点修复/回滚、上下文恢复、GitHub 前置能力排序和补测、代理错误恢复、冻结断言及导出/打包链路。依据：[原实施后复审](8790-improvement-post-review-20261001.md)、[两个运行最新复核](two-runs-latest-review-20261001.md)、[后续改进记录](two-runs-improvement-implementation-20261001.md)。本轮是源码及本地验证，没有再次读取云端运行状态。

## 复核新增发现与修正

| 级别 | 问题及触发条件 | 已实施修正 |
| --- | --- | --- |
| P1 | 等待前置能力的节点补测时，`resume_frozen_acceptance` 只传墙钟期限，没有设置 `_node_deadline`。首轮 `run_specs` 使用 `seconds_available`，因此节点限定 120 秒时仍看到全任务 600 秒；也可能侵占最终阶段预留。 | 补测窗口取节点上限、当前节点余量、全任务余量扣最终预留的最小值；整个验收循环设置同一个硬期限，异常退出恢复原期限。预算不足时保留等待节点，不开始测量。 |
| P2 | 耗时缓存只检查 spec/worker/用例/grader，修改 runner 的 timeout 后仍用旧的 40 秒窗口；独立 runner 的 1 秒测量也能把默认 runner 窗口缩为 30 秒。 | 匹配 timeout 和隔离执行方式；独立 runner、候选执行不训练默认节点窗口。配置不匹配回到按 case/timeout 的估算。 |
| P2 | 新增的耗时元数据读取发生在实际验收前。生成测试目录缺失或选择元数据读取失败时，可能抛 TypeError/OSError，覆盖验收器应返回的 origin/load 错误或其他实际结果。 | 元数据常见读取/结构错误只记录不可用；不缓存、不复用未知范围，使用估算。实际验收器继续执行其权威检查；取消异常和实际执行异常不被吞掉。 |

上述复现先运行在修正前源码，保存于 [复现日志](../diagnostics/overall-review-20261001/reproductions-before.log)。新增 `test_overall_review.py` 共 8 项回归，覆盖实际补测验收入口、最终预留、异常恢复、timeout/runner/隔离方式变化及元数据读取错误。初版预算修正曾从较短节点余量再次扣全任务最终预留，异常恢复测试中的 120 秒窗口因此变为 100 秒；复审后调整为分别取最小值，避免重复扣减。

## 原有改动的整体检查

- **状态和恢复**：成功补齐上下文会清空待请求路径；本次未解决拒绝与历史拒绝分离。源码已经部分写入时不重放原生成提示。无时间、无请求、工具关闭时，恢复不能重新增加原额度。
- **验收和回滚**：完整失败可作为耗时样本，0/0、部分执行、启动失败和未知运行时状态不能训练较短窗口。目标和已受影响回归各自预留，修复全过程共享截止时间，测量前恢复节点期限。已有联合验收、回滚及保护行为测试保持通过条件。
- **前置能力**：helper 调用闭包、需求依赖与冻结元数据合并。准备循环先实现成员再测量；实现证据不等于通过 verdict。未知依赖仍拒绝。补测新增的硬期限未改变这些判断。
- **代理**：明确的 proxy_error/EOF 接入原有有限传输重试；普通 400、已报告用量、成功响应后的中断、single_attempt 和时间不足不扩大重试。未知用量不当作零费用。当前 GLM 相关已有工作区改动也通过本地请求参数/用量回归；没有对线上提供商进行实测。
- **冻结断言**：GitHub 密码错误可有一条或两条合法可见反馈，隐藏/无关反馈不满足。Sheet 保存失败注入与具体 API 路径解耦，校准覆盖单元格/整工作簿写入、自动重试及通用错误反馈，并拒绝未正确回滚的实现。
- **导出与打包**：冻结文件摘要通过完整性审核；Rust 导出保持 setup 元数据与节点导出范围。实际提交脚本在隔离目录执行，核对包内主程序和四个相关模块内容与工作区完全一致。

## 尚需生产验证的边界

测量窗口依然是准入估算，不保证新修改引起的所有慢行为或新回归都能完成。公共入口存在实现证据后也可能有运行时错误，仍须真实验收；静态排序不证明 Search、teams API 或 Editor 业务逻辑正确。

此前记录的跨模块导出机械修复入口尚未接入执行路径；云端最新完整源码未取得，不能据日志安全地自动重写其模块或拆分 Editor。该项仍是后续优化，非本轮修复效果的证明。

当前改动仍在本地工作区，两个旧云端进程不会热更新。更改冻结断言需要以当前源重建内核，仅打 Python 包无法更新旧内核中的测试。上述本地检查不能替代新版本完整运行和官方最终通过率。本轮没有部署、发布、取消、重启或新增付费模型运行。
