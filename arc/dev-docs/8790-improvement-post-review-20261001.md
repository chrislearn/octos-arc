## 复审发现与已处理的问题

1. **普通拓扑排序不能解决准备循环。** 实现顺序使用可终止的依赖遍历，报告循环；测量在循环内其他成员有实现证据后恢复。实现证据仅允许开始测量，不设置通过 verdict。
2. **必须合并原始需求依赖。** 只读取 helper 元数据会遗漏创建组织和 PR 创建等声明依赖；现与原图合并，并有 PR 准备循环及团队依赖的回归检查。
3. **旁路测量也需要前置判断。** tiny tier 和截断回复后的现有应用探测均补上同一入口检查，防止绕过等待状态。
4. **不能遗漏发布清单。** 新模块已加入真实 pack.sh，在独立临时目录执行打包并核对 ZIP 内源文件，未覆盖现有用户提交包。
5. **旧测试夹具兼容。** 首轮全量检查暴露无依赖数据的裸 Flow/Mock 实例兼容问题；已将无冻结依赖时的处理变为立即返回，并通过原验收、修复模式和菜单时序检查。GitHub 运行夹具也支持正确的套件名称。
6. **冻结后格式变化会改变身份。** 保留当前密码 spec 的格式，并同步配方，再完成独立的 GitHub 审核和冻结；配方重现与目录身份校验均验证。没有绕过完整性保护。
