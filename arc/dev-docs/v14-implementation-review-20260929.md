## 已实施

| 阶段 | 改动 | 准入边界 |

| A2 | 新增私有后台测试流水线，在独立目录按小批次沿用义务、场景、编译、独立审核和修正流程。文本请求使用现有隔离请求器，代码期一个测试请求在途；主线程在原 wave 与 sequential 检查点收取结果，复核需求、spec、helper、fixture 与用例哈希后写正式文件。已批准且依赖有实现证据的用例才进入检查点。 | 后台不编辑共享源码或正式套件；旧版本结果丢弃。浏览器执行在源码请求结束的检查点进行。代码阶段缓存和 p90 持续退化时停止后台新请求。 |
| B2 | 场景拒绝原因按尝试和剩余无效项分类，并单独统计唯一拒绝场景；现有确定性 DSL 编译继续先于模型重试。测试提示的设计部分按 phase 取拥有者相关条目，共同规则保持稳定前缀。相同源码版本反复请求 `NEEDS_CONTEXT` 时，修复转到本地检查路径。现有类别设计恢复及全局校验继续用于大设计。 | 裁剪的是设计上下文，不是原需求义务或代码生成契约。拒绝计数不改变准入。 |

## 仍需同预算真实运行验证

1. 当前提供方的图像消息格式、鉴权和 usage 字段需要一张真实参考图的最小请求确认。无可用视觉路由时会记录 `unsupported` 并继续文本路径；本地测试没有宣称线上视觉效果。
2. 后台多阶段文本流水线已用私有工作区和合成请求验证，但尚无真实提供方运行。因此首个已批准用例出现时间、实际墙钟、限流、代码 prompt cache hit、未缓存 token 与 p90 的净变化仍未知。缓存阈值能触发暂停，不代表已证明缓存改善。
3. A0 的零秒窗口根因已按可执行用例修正，但“增加几百秒”只是待首跑日志回放验证的假设。固定预算可能改变最终实现节点数；需同时比较实现率、已执行行为覆盖和健康余量。
4. 本轮未执行 ARC-Bench 官方验收，也未完成方案要求的原版、A0、A0+B1、A2、B2、C 分阶段同预算对照。不得据本地单测推断官方评分或误批准率。

## 复核结论

本地检查支持这次修改的主要安全边界：未审核用例不能通过检查点、过期后台结果不能被提交、图片证据不能直接充当行为断言。正式收益及视觉接口兼容性必须由真实同预算运行确认；在这些数据出现前，v14 应视为待运行验证的实现，而不是已证明优于 v13 的版本。
