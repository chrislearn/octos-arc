# v14：全量验证与参考图证据的合并方案

日期：2026-09-29。分支：`v14`，基线：`v13` 提交 `62192302`。**状态：最终方案与静态复核；本轮不实施运行时代码。** 本方案合并 `v13.3-full-mode-improvement-plan.md`、`visual-reference-preflight-report-20260929.md` 和 `full-mode-pipeline-scheduling-review.md`。各报告中的续跑样本时间不同，数字只作为各自快照，不相加，也不推断线上评分。

首轮 7,200 秒 sheet 运行中，24 个实现叶节点均被尝试，但独立审核窗口为 0 秒，全部仍无业务测试判定；设计和实现请求耗时之和约为 882 秒、5,170 秒，实现阶段提供方报告的 prompt cache hit 为 63.9%。续跑虽有已批准行为用例和真实修复，它复用了已有应用，不能当成首轮覆盖率。视觉报告的续跑快照又晚于全量报告的快照，事件数不能合并统计。

## 实施顺序

1. **A：验证调度。** 在模型代理和设计完成后启动有界测试准备；代码生成不等待慢测试。已批准用例在节点依赖已实现且应用可启动的安全检查点运行，末尾有实质验证额度。支持 sequential 和 whole-app wave 两条路径；`full` 默认与独立审核规则不变。
2. **B：降低返工。** 测试提示仅携带当前 phase 相关设计/需求，稳定共享前缀；对 `quote_invalid` 做最多一次证据重审；超长 blueprint 审核按拥有关系分片，并保持全局一致性/覆盖检验；修复诊断与源码哈希绑定，变更后先重新检查。
3. **C：可信视觉证据。** 安全解析本地参考图、内容哈希去重、状态/来源记录；有明确视觉端点和凭据时才做受控调用。先把经校验观察用于相关节点的设计和导航提示；无图、接口失败或超预算时不影响原流程。保留现有字面量准入。视觉独有断言及代码覆盖插桩留待单独试点。
4. **分阶段测量。** 分别统计 discovered、approved active、passed、failed、unreviewed、invalid、disputed 与完整场景覆盖；按实现/测试阶段记录 provider 缓存和端到端墙钟。先离线单测与固定日志回放，再在相同模型/预算下比较原版、A、A+B、A+B+C。视觉模型真实接口契约必须经最小请求确认；没有该环境时不宣称视觉已验证。

## 不跨越的边界

- 需求 YAML 与官方测试是权威；参考图是可见外观的证据，模型描述是候选解释。不能从图片推断持久化、权限、错误码或 CSV 格式。
- 后台只能处理冻结输入与私有文件；Flow 状态、共享源码、正式测试文件、保护快照由主线程提交。Playwright 与共享源码编辑不并发。慢测试不能阻断代码；未审核测试不能驱动修复。
- 代码实现阶段继续只接收确定性需求契约。参考图摘要仅在设计/节点 UI 相关部分按需附加，不能插入静态系统提示前缀；缓存变化用同阶段 provider usage 测量。
- 固定预算可能减少实现节点，质量比较同时看实现率、已执行行为覆盖和成本。无官方测试时，派生测试通过也不等于 ARC-Bench 官方通过。

## 复核结论

合并后不存在必须二选一的目标冲突；冲突在于**时序与信任层级**。视觉读取移到代理就绪后、设计前；测试准备与代码生成并行但测试执行只在安全边界；测试审核证据与图片证据各自独立校验。最难的工程风险是后台多阶段测试工作对 Flow 共享状态和 token 记账的耦合，因此必须先拆纯函数和建立阶段级预留，不能把现有 `prepare_derived_spec_batch()` 整体放进线程。视觉接口仍缺当前平台契约证据，实际调用应为有条件能力，失败自动降级并记录原因。

v14 验收须证明：无图/禁视觉时回归行为不变；图片越界或缺失不读外部文件；未审核视觉断言不可执行；慢测试时后续代码仍推进；有已批准测试时会实际执行并明确源版本；代码阶段缓存命中和未缓存 token 没有因调度被静默混在总比率中；最终状态不把 `not_run` 算作通过。

## A 阶段的具体调度合同

现有 `OrderedSpecRequests.ordered()` 是同步迭代器。简单地在节点末尾调用 `review_derived_after_implementation()` 会等慢模型；把整个 `prepare_derived_spec_batch()` 搬进线程则会与代码生成争写 Flow、测试文件和保护快照。这两种做法均排除。

先将测试批次拆为不可变输入、私有文本/纯函数处理、主线程提交三段。输入包含 phase、节点 ID、需求/夹具/helper 哈希、提示族、截止时间。隔离 worker 在自己的临时目录完成小批次的义务提取与独立复核、场景提议与确定性编译、独立用例审核以及必要的一次修正/复审；每一阶段仍是新的无工具模型请求，审核器不接收应用源码或运行结果。worker 只能返回原始回复、候选脚本、审核证据和用量，不能直接把状态改为批准。即使主线程正在等待一个长代码 turn，worker 也能在私有数据上推进到下一测试阶段。

主线程在代码 turn 或 wave 完成时非阻塞地收取**已完成**批次，重新运行现有解析、编译、哈希及引文校验，再提交文件、审核结果、账本与保护快照。不同独立批次可乱序完成；同一节点的义务、场景、审核必须有序。迟到结果只要输入哈希或实际 case 哈希与当前版本不一致，保持 `unreviewed`，不能当作新的准入。后台请求每阶段原子预留最坏情况 token；完成时立即按提供方 usage（缺失时按保守估计）结算，不能等主线程结束长代码 turn 才释放，也不能提前预留整条多阶段链的上界。取消、超时和重试按请求 ID 只记一次。

节点代码已完成而测试未生成时标 `implemented_unverified`，立即处理下一个可入队节点。检查点仅在有新增 `approved_behavior`、其依赖代码均已实现、应用可构建启动且夹具能可靠隔离时运行已批准子集；否则继续代码生成并记录 `waiting_for_dependency` 或具体不可执行原因。Playwright 与共享源码编辑不并发。用例审核绑定需求/用例/helper/夹具哈希，**执行判定另绑源码摘要**；后续源码改变使相关运行结论待复测，但不自动撤销未变用例的独立审核。运行失败须经原有失败争议审核才能驱动修复。大套件保留至最终阶段。

收尾仅使用一份 reserve：`R_health` 是最后构建、启动、浏览器复查；`R_suite` 按**已批准活跃用例**的优先子集估计执行、最小修复与复测；`R_tail` 是一个有上限的最后审核窗口，按近期有效阶段耗时 p90 或同类任务历史估计。新实现任务的准入边界取现有 `final_phase_reserve()` 和 `R_health + R_suite + R_tail` 的较大值，不能再叠加第二整份 reserve。`R_tail` 的可选部分受总预算约 25% 的上限约束，健康检查与已批准用例优先。到边界后 `final_phase_due()` 应真正停止接纳新的源码节点；whole-app wave、顺序节点和单次 whole-app 生成都要遵循，不能只改一条路径。若末尾没有可执行用例，准确交付未验证状态及卡住阶段，不能以页面健康代替业务通过。

## B 阶段的证据质量与提示成本

需求义务按成功、拒绝、持久化、权限及仅 UI 分类，优先为缺少动作后结果的分支补测试。测试提示保持 DSL 和共同规则的字节稳定前缀，变量内容仅放当前 phase 的关联需求、设计切片、义务和必要夹具。失败重试只送出错目标、原始需求证据、失败提案与具体校验错误。裁剪前后逐目标比较需求 ID、GIVEN/WHEN/THEN、负面分支、精确字面量与输出格式；任何漏项都退回原提示，不能用机械截断换低 token。实现阶段继续只向代码模型提供确定性需求契约，尚未审核的测试不进入其 prompt。

独立审核可只携带本用例实际调用的 helper 函数与传递依赖，但必须保留完整 helper 的哈希，并允许缺上下文时退回全 helper。为需求片段和测试断言提供可选择的编号可减少模型抄错引文；程序回填原文后仍运行全部现有 `review_validation_errors`。对 `quote_invalid` 最多一次只读重审：固定需求、用例与 helper 哈希，重新问完整 THEN 是否由动作后的断言证明；模型承认缺失时判 `needs_correction`，不能给较弱断言签发批准。

Blueprint 超上下文时按 phase 与共享实体所有权切分：每片保留原需求、属于本片的领域字段和跨片依赖摘要；合并前确定性检查需求 ID 全覆盖、实体身份/存储所有权、命令与路由唯一性、跨片引用。局部通过只提升局部可信度，缺片/冲突保持全局 `unverified`。修复提示中的路由或源码诊断绑定文件哈希与问题键；下轮引用前重跑对应静态检查，已消失则丢弃旧行号，仍存在则引用当前行；真实运行时失败不能只因版本变化而抹除。

## C 阶段的参考图门槛

机械编译保持原位置。代理/驱动就绪且任务没有官方测试时，对需求中图片路径做目录内实路径检查，拒绝绝对路径、`..`、越界符号链接、远程 URL、非图片、超大小和无法解码文件。相同内容按 SHA-256 去重；证据记录路径、引用节点、原文、图片哈希、状态、模型/提示版本和短观察。缓存键至少覆盖图片哈希、模型/端点、提示版本和相关需求上下文哈希。缺图、超预算、调用失败或模型回复不合格均明确记状态，并继续原有文本流程。

实际视觉请求先用**当前运行环境**的一张非敏感小图验证端点、鉴权、图像消息格式、响应格式与用量字段；历史截图和日志不能代替这一步。视觉请求另限张数、墙钟、token/费用；不记录凭据或完整 base64。模型只报告可见文字、控件、布局、状态和不确定项，禁止把推测的点击结果、持久化、权限或 CSV 格式写成事实。视觉摘要按节点/phase 限长，放在变量提示尾部。图片独有名称或静态断言若将来要进入可执行测试，需另一独立审核看到原图、需求引用、具体断言及图片哈希，并再次通过 DSL 与用例校验；首阶段不扩大 `allowed_literals`。

## 缓存、指标与分阶段验收

代码的系统消息、规则、源码顺序和需求契约前缀保持稳定。测试按提示族先发送第一笔真实请求，再有限并发；代码生成期间从 1 个测试文本请求在途开始，空闲/收尾时才评估 2 个。隔离 proxy 不保证提供方远端缓存互不驱逐，必须记录 provider 返回的 prompt tokens、cache hit tokens、未缓存 tokens、模型/路由/提示族和请求 p50/p90；无 usage 标 `unknown`。分别计算实现与审核的缓存指标，不能用总体比例掩盖实现阶段回退。灰度期间如同任务同模型的实现缓存命中持续比串行对照低超过 5 个百分点，或未缓存输入 token 多超过 10%，先暂停代码期后台请求，在空闲/收尾继续；阈值需多次运行确认，不因单笔请求触发。

统一用例漏斗：`discovered / proposed / structurally_valid / approved_active / passed / failed / excluded_unreviewed / excluded_invalid / disputed`；另报源需求场景和负面合同的完整覆盖，以及实现、未验证、部分验证状态。被 Playwright 隔离的用例不得算进业务通过率。前后端代码行/分支覆盖属于后续可选插桩，只能由已批准用例的实际执行测得，并与需求行为覆盖分开。

| 阶段 | 必须通过的离线/回放核验 | 同预算真实运行要比较 |
| --- | --- | --- |
| A | 慢 A 测试不阻塞 B/C 代码；长 whole-app turn 中测试小批次可完成多阶段；乱序批次仍按节点阶段提交；旧哈希不准入；预算取消只记一次；两种代码生成路径都留出实际收尾。 | 首个活跃用例出现与执行时间、已实现节点数、完整验证节点数、最终健康和总墙钟。 |
| B | 提示裁剪不丢义务/精确值；错误引文、动作引文、旧版本不准入；blueprint 缺片不标全局通过；消失的旧行号不再影响修复。 | 无效提案/重试、审核批准率、误批准数、prompt 未缓存 token、代码阶段缓存与成本。 |
| C | 越界、符号链接、缺图、坏图、同图重复、预算尽和无效模型回复均有状态与回退；开关关闭或无图时原流程不变；图片独有断言不能运行。 | 图像证据进入相关提示的数量、额外视觉费用、真实行为覆盖与 A+B 的增量。 |

对照按原版、A、A+B、A+B+C 逐阶段进行，固定需求、模型、路由、总预算和并发限制。只有比较 C 与 A+B，才能归因视觉预处理的净收益；生成脚本数、页面健康和主观相似度都不能代替业务验证。

## 最终复核

时序复核：机械测试先于代理，视觉准备在代理后设计前；AI 测试文本与代码并行，共享写入和浏览器测试只在安全边界。信任复核：YAML/官方测试最高权威，图片观察不是行为预言机，引文重审保持严格校验。预算复核：慢测试不阻塞代码，收尾不再让代码无限挤占审核，但固定总预算仍可能减少实现节点，必须同时报告实现率和验证率。缓存复核：稳定代码前缀与分阶段 provider usage 是验收依据，不能预先承诺命中率或评分提升。

**未验证的事项：** 当前平台视觉 API 契约、后台多阶段调度的运行表现、真实缓存净收益和 ARC-Bench 评分都需未来实施后测量。本轮按最新用户要求只保留方案文件，`v14` 上不保留运行时代码改动。
