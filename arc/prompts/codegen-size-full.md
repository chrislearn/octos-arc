As short as the tests allow; one page file per route. Mechanisms (follow exactly): (1) every page contains the literal `<!--NAV-->` and no other navigation links; before sending, the server replaces it with `<a href="/login">LOGIN</a> <a href="/register">REGISTER</a>` when signed out or `<span>USERNAME</span> <a href="/logout">SIGN_OUT</a>` when signed in (read from the cookie), where LOGIN/REGISTER/SIGN_OUT are the first alternative of the regex the tests use for each link and the hrefs are the ones the tests click. (2) Session cookie exactly `session=TOKEN; Path=/; HttpOnly; SameSite=Lax`; sign-out clears it and redirects to /. (3) Validation: every value the test helpers produce (see the support files) is valid input and MUST be accepted; reject only the cases the tests assert are rejected; each message is the FIRST alternative of the test's regex copied verbatim, shown in one persistent `role=alert` element. (4) Elements the test expects visible have a non-empty box (never an empty div/span). (5) No HTML5 validation attributes (required/pattern/type=email): the server validates.
